## A. 큰 그림 (왜 이 순서인가)

종훈님 핵심 불만은 **"전역이 작고 잡다하다"** + **"히어로가 주인공이어야 한다"** + **"풋터가 빈약하다"** 입니다.
따라서 **① 전역 스케일(폰트·간격·컨테이너) 업스케일을 먼저** 깔고(모든 화면이 시원해짐) →
**② 히어로를 주인공으로(깔끔한 애니메이션)** → **③ 스크롤 섹션 큼직하게** → **④ 리치 풋터** →
**⑤ 다른 화면 순차 롤아웃** 으로 갑니다. 스케일을 먼저 잡아야 이후 모든 작업의 기준이 안 흔들립니다.

## B. 단계별 상세

### Phase 1 — 전역 토큰 "스케일업" 정의 ★종훈님 1순위 불만 대응★

**1.1 색 토큰** (analysis §2 실측 확정)
| 역할 | 값 | 비고 |
|------|----|----|
| page / sunken / surface | `#E9ECF1`~`#EEF1F5` / `#F2F5FA` / `#FFFFFF` | 청회색·구획·면 |
| ink heading/body/**sub**/caption | `#1A2434` / `#333D4B` / **`#565D6A`** / `#8E929B` | 보조는 #565D6A(AA 6.7) |
| line | `#D6D8DB`~`#E1E4EA` | 헤어라인 |
| brand / strong | `#3182F6` / `#1B64DA` | 금액·CTA는 strong(AA 5.4) |
| accent / danger | `#06BE7B`·`#047857` / `#F04452` | 채용 그린 / 긴급 |

**1.2 ★사이즈 토큰 업스케일★** (현행 → 제안 — "작다"의 해결)
| 항목 | 현행 | 업스케일 제안 | 효과 |
|------|------|--------------|------|
| 콘텐츠 컨테이너 max-w | 1080px | **1200~1280px** | 데스크톱 시원 |
| 히어로 헤드라인 | ~32px | **40~52px(clamp)** | 주인공감 |
| 섹션 타이틀 | ~18px | **24~28px** | 큰 섹션 |
| 본문 | 14~15px | **15~16px** | 가독 |
| 보조/캡션 | 11~12px | **12~13px(하한 12)** | 고령 배려 |
| 섹션 간 간격 | gap 24px | **40~64px** | 호흡 |
| 주 CTA 높이 | 54px | **56~60px**, 폰트 16~17px | 큼직 |
| radius | 12~20px | 데이터 8~12px(업비트 4 절충) | 정돈 |
| 숫자 | sans | mono+tabular-nums | 자릿수 정렬 |

**1.3** 이 단계 산출물은 토큰표. 우선 홈 시안에만 적용(전역 config는 Phase 3). **게이트 1.4**: 종훈님 확인(특히 컨테이너 폭·헤드라인 크기·간격).

### Phase 2 — 홈 시안(히어로 중심 재구성) · 이번 사이클에 코딩

**작업 노드**:
1. **❌ 제거** — 상단 통계 스트립, 우측 '내 권리 요약 250만원' 카드(종훈님 X 표시).
2. **히어로** — 좌: 큰 헤드라인(40~52px) + 부카피 + **CTA 2개**(내 퇴직금 캐치하기=brand-strong / 단기알바=회색·green) + **캐러셀 점**(현행 7초 로테이션을 점 인디케이터로 시각화). 우: **깔끔한 Framer 모션 비주얼** — 트리맵(canvas) 대신 **수령액 카운트업 + 4대 수당 타일이 부드럽게 등장**하는 절제된 모션(조잡한 난수 X).
3. **작동방식 3스텝** — "PDF 올리기 → 자동 계산 → 결과 확인" 큰 카드 3개.
4. **4계산기 큰 카드** — 퇴직금/실업급여/주휴/연차(+혜택) 큼직하게.
5. **채용** — 행 리스트(업비트 톤) 또는 큰 카드. 기존 fetch 로직 보존.
6. **신뢰/혜택 피처카드 3** — "100% 무료 / 안전 보관(개인정보) / 정밀 계산(28일 블록)" (업비트 cold-wallet 피처 차용).
7. **리치 풋터** — 피처와 별개로: 고객센터/1:1 문의 + **4단 컬럼**(계산기·가이드·고객지원·회사/정책) + 회사·면책 줄("참고용·노무사 상담") + 배지/SNS(있으면) + 앱링크.

**리뷰 교훈 선반영(Phase 0.3 더블리뷰 A·B 적출 — 반드시 클리어)**:
- [ ] 보조 텍스트 **#565D6A**(흰 위 AA 4.5↑). 캡션 `#8E929B`는 날짜 등 비필수만.
- [ ] 금액색 `brand`→**`strong`(#1B64DA)**. 긴급/뱃지 대비 AA.
- [ ] 비동기 패널 **스켈레톤**(공지·채용 로딩 대칭, FOUC 제거).
- [ ] 모든 flex 자식 `min-w-0`+truncate, 320px 잘림 0(grid 기본 1열 명시).
- [ ] 터치타깃 44px, aria, 데드 네비 정리. center_name/benefits 정보 노출 결정.

**검증 2.5**: 320/375/768/1280 실측 + 더블리뷰 PASS until. **게이트 2.6**: 종훈님 육안 승인.

### Phase 3 — 전역 토큰 전환 (리스크 큰 구간)

- `tailwind.config.js`/`index.css`에 Phase1 **스케일·색 토큰 일괄 주입**(toss.* 하위호환 유지).
- 공유 `ui/{Card,Container,SectionHeader,Button,Badge}` + `TopNav`/`BottomNav` 업스케일·헤어라인 정렬.
- **3.3 스모크 게이트** 통과 시 **1차 배포 가능**(전역 스케일 + 홈).

**리스크**: 컨테이너 폭·폰트 업스케일이 모든 화면 레이아웃을 밀어냄 → 직전 Toss 더블리뷰 일부 무효화.
**완화**: 화면별 더블리뷰(Phase 4)로 흡수. 스모크 게이트로 치명 깨짐 선차단.

---

### Phase 4 — 화면별 순차 적용
순서: **계산기허브 → 채용 → 마이 → 결과/리포트 → 공지 → 가이드 → 랜딩 → SEO/약관.**
각 화면: 토큰·스케일 적용 → 라이브 실측 → **더블리뷰** → 커밋 → 배포. 계산 로직 무변경 재확인.

### Phase 5 — 마감
AA 전수·320px 전수·Lighthouse·최종 더블리뷰 → **main 최종 배포**.

## E. 종훈님 결정사항 (승인 시 함께)
1. **컨테이너 폭**: 1200 vs 1280(업비트 1360에 더 근접)?
2. **히어로 헤드라인 크기**: 40px vs 48~52px(더 큼직)?
3. **히어로 우측 모션**: (a)수령액 카운트업+수당 타일 등장 (b)일러스트 모션 (c)단순 정적 일러스트 — 선호?
4. **숫자 폰트**: mono(자릿수 정렬) 적용?
5. **모바일 스케일**: 데스크톱만 크게 vs 모바일도 함께 크게?
6. **풋터 전화번호**: CATCH는 대표번호 없음 → "1:1 문의/카톡 채널" 로 대체 OK?
