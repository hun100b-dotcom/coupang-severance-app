# CATCH 업비트풍 리디자인 — 전문가 워크트리 (실행 분해 계획)

> **이 문서가 1차 승인 대상입니다.** `upbit_home_analysis.md`(홈 정밀분석)를 근거로,
> 업비트 홈의 비주얼 언어를 CATCH에 **어떤 순서·과정·단계**로 적용할지 전문가 수준으로 분해합니다.
> **종훈님이 이 워크트리를 승인한 뒤에야 홈 시안 본격 코딩으로 넘어갑니다.**
> (이미 만든 `redesign/upbit-home` 브랜치의 Home.tsx는 "선행 탐색 프로토타입"으로, 워크트리 검증에 쓰인 참고물입니다.)

## A. 큰 그림 (왜 이 순서인가)

업비트풍의 정수는 **개별 화면 장식이 아니라 "토큰(색·여백·모양·타이포)"** 입니다.
따라서 **토큰을 먼저 정의(단, 전역 적용은 보류)** 하고 → **한 화면(홈)에서 완성형으로 증명** →
**종훈님 승인** → **전역 토큰 전환** → **화면별 순차 적용**의 순서가 안전합니다.
화면부터 일괄로 바꾸면 토큰이 흔들릴 때 전 화면을 다시 손대야 하므로 금지.

```
업비트풍 리디자인 워크트리
│
├─ Phase 0  분석·기준 확정 ........................... [현재, 거의 완료]
│   ├─ 0.1 업비트 홈 정밀 실측 ......................... ✅ upbit_home_analysis.md
│   ├─ 0.2 선행 홈 프로토타입(탐색용) ................... ✅ redesign/upbit-home (참고물)
│   ├─ 0.3 더블리뷰로 함정 사전 적발 ................... ✅ A:조건부PASS / B:FAIL → 교훈 확보
│   └─ 0.4 ▶ 이 워크트리 승인 ......................... ⏳ 종훈님
│
├─ Phase 1  디자인 토큰 정의 (적용은 홈에 한정) ........ [승인 후 착수]
│   ├─ 1.1 색 토큰 확정 (analysis §2 기반)
│   ├─ 1.2 타이포/여백/radius/shadow 토큰 확정
│   ├─ 1.3 토큰을 "홈 범위"에만 우선 주입(전역 미변경)
│   └─ 1.4 ▶ 게이트: 토큰표 종훈님 확인
│
├─ Phase 2  홈 완성형 시안 (토큰 기반 재작성) .......... [Phase1 직후]
│   ├─ 2.1 지표 스트립 / 히어로 / 데이터2단 / 공지 / 가이드 / 푸터
│   ├─ 2.2 리뷰 교훈 반영(대비·로딩·정보회귀) 전부 클리어
│   ├─ 2.3 320/375/768/1280 실측 + 더블리뷰
│   └─ 2.4 ▶ 게이트: 종훈님 홈 육안 승인
│
├─ Phase 3  전역 토큰 전환 (모든 화면 영향) ............ [홈 승인 후]
│   ├─ 3.1 tailwind.config.js / index.css 토큰 교체
│   ├─ 3.2 공유 컴포넌트(ui/*, TopNav, BottomNav) 정렬
│   └─ 3.3 ▶ 게이트: 전 화면 스모크 점검(깨짐 0)
│
├─ Phase 4  화면별 순차 적용 (각 화면 더블리뷰) ........ [전역 후]
│   └─ 계산기허브 → 채용 → 마이 → 결과/리포트 → 공지 → 가이드 → 랜딩 → SEO/약관
│
└─ Phase 5  마감 (회귀·접근성·성능 전수) .............. [마지막]
    └─ AA 전수 / 320px 전수 / Lighthouse / main 배포
```

## B. 단계별 상세 (전문가 분해)

### Phase 1 — 디자인 토큰 정의 (적용은 홈 한정)

**목표**: "이 색·이 폰트·이 여백" 을 숫자로 확정. 화면마다 즉흥 색 쓰는 일 차단.

| 토큰군 | 확정값(analysis §2~5 실측 기반) | 비고 |
|--------|-------------------------------|------|
| 배경 page | `#E9ECF1`~`#EEF1F5` | 청회색 |
| 면 surface | `#FFFFFF` / `#FCFCFD` | 카드 |
| 구획 sunken | `#F2F5FA` | 띠·표헤더 |
| 잉크 ink-heading | `#1A2434` | 남색 헤딩 |
| 잉크 ink-body | `#333333`→토큰 `#333D4B` | 본문 |
| 잉크 ink-sub | **`#565D6A`** | 보조(AA 6.7:1) ← 직전 시안 #8B95A1 폐기 |
| 잉크 ink-caption | `#8E929B` | **비필수 캡션만** |
| 보더 line | `#D6D8DB`~`#E1E4EA` | 헤어라인 |
| 포인트 brand | `#3182F6` / 강조 `#1B64DA` | 금액·CTA는 strong(AA 5.4) |
| 채용 accent | `#06BE7B` / `#047857` | 그린 유지 |
| 위험 danger | `#F04452` (텍스트는 더 진하게) | 긴급 전용 |
| radius | 데이터 8px / 버튼 8px | 업비트 4px를 소비자앱용 8px로 절충 |
| shadow | float 최소화 → border 우선 | 평평한 면 |
| 숫자 | mono(JetBrains) + tabular-nums | 자릿수 정렬 |

**산출물**: `tasks/plans/` 토큰 확정표(또는 본 문서 갱신). **이 단계에선 전역 config 미변경**.

**게이트 1.4**: 종훈님이 토큰표(특히 배경 청회색 강도·radius 8px·숫자 mono 여부) 확인.

---

### Phase 2 — 홈 완성형 시안

**작업 노드(각각 독립 커밋 가능)**:
1. **지표 스트립** — 평균 퇴직금·실업급여 상한·최저시급·누적확인. 라벨 `ink-sub`, 숫자 mono. `min-w-0`로 라벨 줄밀림 방지.
2. **히어로** — 좌(36px급 헤드라인 + CTA 2개[퇴직금=brand-strong / 채용=회색·green]) / 우(내 권리 요약 데이터 패널, tabular). 평평·헤어라인.
3. **데이터 2단** — 좌 2/3: 계산기 5행 + 채용 행 리스트 / 우 1/3: 공지 패널.
4. **가이드 배너** — 남색 평면.
5. **푸터** — 12px 조용.

**리뷰 교훈 선반영(반드시 클리어할 체크리스트)** — Phase 0.3 더블리뷰 적출:
- [ ] `ink-sub`를 **#565D6A**로(흰 위 AA 4.5↑). 캡션 `#8E929B`는 날짜 등 비필수만.
- [ ] 채용 임금색 `brand`→**`brand-strong`(#1B64DA)**.
- [ ] 긴급/내일 뱃지 대비 AA 충족(배경·글자 톤 조정).
- [ ] 공지 패널에 `useNotices.loading` 받아 **스켈레톤**(채용과 대칭, FOUC 제거).
- [ ] 지표 스트립 라벨 등 모든 flex 자식 `min-w-0` + truncate.
- [ ] 채용 행에서 빠진 `center_name`·`benefits` **정보회귀 여부 결정**(노출/생략).
- [ ] 터치타깃 44px, aria, `/landing` 등 데드 네비 정리.

**검증 2.3**: 320/375/768/1280 라이브 실측(오버플로 0, 잘림 0, 대비 AA) + 더블리뷰(A총괄·B적대) PASS until.

**게이트 2.4**: 종훈님 홈 육안 승인 → Phase 3 진입.

---

### Phase 3 — 전역 토큰 전환 (리스크 큰 구간)

- `tailwind.config.js`: page/ink/line/radius/shadow 토큰을 Phase1 확정값으로 **교체**(기존 toss.* 하위호환은 유지).
- `index.css`: AnimatedBackground 톤·그림자·전역 input 스타일 정리.
- 공유 `ui/{Card,Container,SectionHeader,Button,Badge,Chip}` + `TopNav`/`BottomNav`를 토큰에 맞춤(예: Card radius 20→12·그림자 축소, 글래스 잔재 정리).

**리스크**: 전역 토큰은 **모든 화면에 즉시 전파** → 직전 Toss 더블리뷰가 무효화되는 화면 발생.
**완화**: 3.3 스모크 점검(전 라우트 1회 렌더, 깨짐/오버플로/콘솔에러 0) 통과해야 Phase 4.

---

### Phase 4 — 화면별 순차 적용

순서(영향도·트래픽 기준): **계산기허브 → 채용 → 마이페이지 → 결과/리포트 → 공지 → 가이드 → 랜딩 → SEO/약관.**
- 각 화면: 토큰 적용 → 라이브 실측 → **더블리뷰** → 로컬 커밋(미푸시).
- **계산 로직(28일 블록) 무변경** 원칙 화면마다 재확인(결과/리포트 화면 특히).

---

### Phase 5 — 마감

- 접근성 AA 전수(대비·포커스링·aria), 320px 전수 오버플로 0, Lighthouse(성능/접근성), 콘솔 0.
- 최종 더블리뷰 → 종훈님 최종 승인 → **그때 비로소 main 배포**.

## C. 검증 프로토콜 (모든 Phase 공통)

1. `npx tsc --noEmit` 0 에러 + `npm run build` 통과.
2. 라이브 실측(로컬 dev): 320/375/768/1280 — 가로 오버플로 0, 텍스트 잘림 0.
3. 대비: 본문/보조 텍스트 AA(4.5:1), 큰 텍스트 3:1.
4. **더블리뷰**: A(총괄) + B(적대) → BLOCKER 0까지 반복(최대 2회).
5. 콘솔 에러 0. 계산 로직 diff 0(UI만).

## E. 종훈님께 필요한 결정 (승인 시 함께 알려주시면 됩니다)

1. **배경 청회색 강도**: 업비트 원본 `#E9ECF1`(진한 편) vs 절충 `#EEF1F5`(밝은 편) — 어느 쪽?
2. **모서리(radius)**: 업비트 원본 4px(각짐) vs 절충 8px(약간 둥금) — 어느 쪽?
3. **숫자 폰트**: 금액을 mono(JetBrains, 자릿수 정렬)로? 아니면 일반 Pretendard 유지?
4. **정보밀도 vs 가독성**: 일용직 고령 사용자 고려해 "밀도 보통+큰 글자" vs "업비트급 고밀도" 중 선호?
5. **롤아웃 범위**: 이번엔 홈만 완성 후 멈춤 → 승인 시 전역, 인가? (권장: 홈 먼저)
