# CATCH × 업비트풍 디자인 방향 문서

> **목적**: 종훈님이 "가장 추구하는 웹페이지 형태"로 지목한 **업비트(upbit.com)** 의 디자인 골격을
> CATCH(퇴직금·실업급여 계산기)에 맞게 차용하기 위한 방향 정의서.
> **작성 근거**: 추측이 아니라 2026-06-30 실제 `upbit.com/home` · `upbit.com/exchange` 를
> 브라우저로 직접 열어 DOM의 `getComputedStyle` 실측값을 추출했습니다. (헥스값 = 실측 RGB 환산)
> **범위(이번 단계)**: 분석 + 방향 정의 + **홈 화면 시안 1장**. 전역 일괄 적용·main 배포는 종훈님 홈 시안 승인 후 별도 진행.

---

## 0. 한 줄 요약 (비전공자용)

업비트는 "**조용한 회색빛 바탕 + 빽빽하게 정돈된 숫자 표 + 딱 한 가지 파란 포인트색**" 으로
신뢰감과 전문가 느낌을 줍니다. CATCH는 거래소가 아니므로 **'거래' 요소(빨강·파랑 등락색)는 그대로 베끼지 않고**,
**'정보 밀도 · 정돈 · 차분한 프로 톤'** 만 빌려옵니다.

### 1-2. 타이포그래피

- **폰트 패밀리(실측)**: `Roboto, "Noto Sans KR", sans-serif` — **숫자는 Roboto**로 통일해 자릿수 정렬감을 줌.
- 히어로 헤딩: **36px / weight 700**, 색 `#1A2434`
- 섹션 헤딩: **32px / 700**
- 테이블 헤더: **11px / `#666`**
- 테이블 셀(숫자 포함): **12px / Roboto / 우측정렬**
- 숫자는 사실상 tabular(자릿수 고정) 느낌으로 우측 정렬.

### 1-3. 레이아웃 골격 (실측 구조)

### 1-4. 간격·모양·정보밀도 (실측)

- **테이블 행 높이 45~46px**, 셀 패딩 0~8px → **매우 타이트**.
- **border-radius 4px** (버튼·카드) → 작고 각진 **프로페셔널** 인상. (둥근 토스풍과 정반대)
- 그림자 거의 없음 → **보더(헤어라인) 기반**으로 면을 나눔.
- 그라데이션 최소 → **평평한(flat) 면**.
- 한 화면에 [지표 스트립 + 시세표 + 공지]를 동시에 노출하는 **고밀도 대시보드** 성격.

## 2. CATCH 해석 원칙 (무엇을 빌리고, 무엇을 버리나)

| 업비트 요소 | CATCH 적용 | 판단 |
|-------------|-----------|------|
| 청회색 배경 `#E9ECF1` | ✅ 페이지 배경을 흰색→**옅은 청회색**으로 | 차분·전문 톤 차용 |
| 남색 잉크 `#1A2434` | ✅ 헤딩 색을 남색 잉크로 | 신뢰감 |
| **지표 스트립** | ✅ **"내 권리 지표 스트립"** 신설 (평균 퇴직금·실업급여 상한·최저시급·누적확인) | 업비트 시그니처 차용 |
| 고밀도 표/리스트 | ✅ 계산기·채용을 **카드→촘촘한 표/행** 으로 | 정보밀도 차용 |
| 2단(데이터 + 공지) 그리드 | ✅ 좌 계산기/채용 · 우 공지 | 구조 차용 |
| tabular 숫자(Roboto) | ✅ 금액은 **JetBrains Mono / tabular-nums** | 자릿수 정렬 |
| 얇은 보더, 평평한 면 | ✅ float 그림자·그라데 **줄이고** 헤어라인 강조 | 톤 차용 |
| 작은 radius(4px) | ⚠️ **8px로 절충** | 4px는 소비자앱엔 과하게 날카로움 |
| **상승=빨강 / 하락=파랑** | ❌ **그대로 안 씀** | CATCH에서 돈은 "받는 것"=긍정. 빨강은 **위험/긴급 전용**으로 보존. 금액 강조는 **브랜드 블루** 유지 |
| 거래 버튼(매수 빨강/매도) | ❌ 미사용 | 거래소 개념 없음 |

> **핵심 차별점**: 업비트의 *형태(밀도·정돈·차분함)* 는 차용하되, *의미색 체계(등락 빨강·파랑)* 는
> CATCH의 기존 규칙(블루 메인 + 그린=채용 + 빨강=위험)을 깨지 않도록 **차용하지 않는다.**

## 4. 신규 컴포넌트 패턴 (업비트 차용)

1. **지표 스트립(IndexStrip)** — 얇은 가로 띠. `라벨 + 숫자(mono) + 구분선(divide-x)`.
   CATCH 값: `평균 퇴직금 250만 · 실업급여 일 상한 68,100 · 2026 최저시급 10,320 · 누적 확인 N명`.
2. **데이터 행 리스트(DataRow)** — 카드 대신 표처럼 촘촘한 행. 좌(아이콘+제목+부제) / 우(수치+화살표).
   계산기 5종·채용 공고를 행으로.
3. **공지 사이드 패널(NoticeList)** — 우측 1/3, 날짜 우측정렬 회색, 제목 남색.
4. **헤어라인 분할** — 그림자 대신 `border`/`divide`로 면 구획.

## 5. 적용 원칙 (구현 가드레일)

- ✅ **계산 로직(28일 블록) 절대 불변** — UI/시각/레이아웃만.
- ✅ 무지개 금지 유지: 블루 메인 + 그린(채용) + 회색 + 의미색(빨강=위험만).
- ✅ 접근성: 텍스트 대비 WCAG AA. 작은 폰트(11~12px)는 **회색이라도 대비 확보**, 터치 타깃 44px.
- ✅ 모바일 우선: 2단 그리드는 모바일에서 1단으로 무너뜨림. 320px 오버플로 0.
- ✅ 되돌리기 쉽게: 이번 시안은 전역 토큰 미변경, Home 범위로 한정.
- ⚠️ 정보밀도를 높이되 **고령·저시력 사용자(일용직 핵심 타깃)** 고려 — 업비트 11px를 그대로 쓰지 않고
  본문 13~14px, 표 캡션만 12px로 절충.

## 6. 전역 롤아웃 시 범위·리스크 (2단계 견적)

**범위(승인 시):** `tailwind.config.js`(토큰 5개) · `index.css`(배경/그림자) · 공유 `ui/*`(Card·Container·SectionHeader) ·
TopNav/BottomNav · 그 다음 화면별(계산기 허브·채용·마이·결과 등) 순차.

**리스크:**
- 🔶 전역 토큰(page/ink/line) 변경은 **모든 화면에 즉시 전파** → 화면별 더블리뷰 재실행 필요(직전 Toss 리뷰 무효화분 존재).
- 🔶 정보밀도 상향 = 고령 타깃 가독성과 충돌 가능 → 폰트 하한선 규칙 필요.
- 🔶 그림자 축소 시 일부 화면 위계가 평평해져 **재배치** 필요.
- 🟢 계산 로직·데이터·라우팅 무관 → 기능 회귀 위험 낮음(순수 시각).

**예상 작업량:** 토큰/전역 0.5일 + 화면 18개 순차 적용·더블리뷰 = 큰 작업. **단계적(홈→허브→채용→…) 권장.**
