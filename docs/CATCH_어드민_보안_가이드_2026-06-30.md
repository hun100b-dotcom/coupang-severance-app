# A. 어드민 페이지 가이드

## A-1. 접속·권한
- 주소: `/admin` (슈퍼어드민/관리자 로그인 후)
- 현재 관리자 3명 전부 **super_admin**(최고권한): catchmaster, 종훈님 카카오, 종훈님 구글.
- 권한 단계: `super_admin`(전체+관리자 관리) > `admin`(운영) > `viewer`(열람) — ※ 단계별 차등은 아래 보안가이드 P1 참고(현재 서버 강제 미흡).

## A-3. 관리자 추가 / 권한 부여 (단계)
1. 어드민 → **시스템 → 관리자 계정** 메뉴.
2. "관리자 추가" → 이메일 + 역할(super_admin/admin/viewer) 선택 → 저장.
   - ※ 그 이메일은 **먼저 앱에 일반 회원으로 가입(카카오/구글)** 돼 있어야 로그인 시 매칭됨.
3. 역할 변경·비활성화·삭제도 같은 화면에서.
4. **이 작업은 super_admin만 가능** — DB 규칙(RLS)으로 서버에서 강제됨(일반 admin은 막힘). ✅
5. 확인: 추가 후 목록에 표시되고, 새로고침해도 유지되면 정상 반영(이 화면은 에러처리·재조회가 잘 되어 있음).

## A-4. "디자인이 안 바뀐 것 같다" 설명
- 어드민 개편은 **배포 완료**(커밋 4개 main 반영, 빌드 확인). 미반영·캐시 문제 아님.
- 다만 **레이아웃은 그대로 두고 색·대비·숫자정렬만 통일**한 "절제된" 방식이라 시각 변화가 작음(데이터 빽빽한 관리화면 특성).
  - 예: 배경 `#f8fafc`→`#EEF1F5`(약간 푸른 회색), 무지개색 제거, 금액 자릿수 정렬.
- **확인법:** 어드민에서 `Ctrl+Shift+R`(강력 새로고침) 후 배경이 살짝 푸른 회색 + 숫자 가지런하면 반영된 것.
- 사용자 화면처럼 **확 달라 보이게** 하려면 토큰 통일이 아니라 별도 **레이아웃 개편**이 필요(원하면 진행).

# B. 보안 가이드

## B-1. 보안을 "어디서" 확인하나 (현재)
보안 기능이 메뉴별로 흩어져 있음 (한눈에 보는 통합 화면은 아직 없음):

| 무엇 | 위치 |
|---|---|
| 누가 관리자인가 / 권한 부여 | 시스템 → **관리자 계정** |
| 회원 개인정보 보호 / 마스킹 해제 | 시스템 → **회원 관리** |
| 관리자가 무슨 행동을 했나(감사) | 시스템 → **Audit Logs** / **서버 로그** |
| 악성 IP 차단 | 설정 → **IP 차단** |
| 마스킹 해제 보안키 설정 | 설정 → 보안키(★ 아래 B-4 필수) |

> 💡 원하면 이것들을 한 화면에 모은 **"보안 현황" 대시보드**(관리자 수·최근 감사·차단 IP·노출 점검)를 만들어 줄 수 있음.

## B-2. 이번에 점검·조치한 것 (보안감사 대비)

| 등급 | 항목 | 상태 |
|---|---|---|
| 🔴 | 회원 이메일 비로그인 노출(user_profiles 뷰) | ✅ 차단 |
| 🔴 | 회원 PII 가짜 마스킹 + 해제키 평문·공개 | ✅ 서버측 마스킹+해시키 |
| 🔴 | **관리자 명단(이메일·역할) 비로그인 노출**(admin_accounts) | ✅ **방금 차단**(is_admin 전용) |
| 🟠 | 감사로그 위조 / 알림 임의삽입 / anon 호출 위험함수 | ✅ 권한 제한 |
| 🟠 | 문의 RLS 단일 UUID 하드코딩 | ✅ is_admin 교체 |
| 🟡 | 함수 search_path 미설정 16건 | ✅ 고정 |
| 🟡 | 방문자탭 평문 PII | ✅ 서버측 마스킹 |

→ Supabase 보안 어드바이저 재실측에서 ERROR 0, 핵심 항목 전부 해소 확인.

## B-3. 권한 부여 — 동작/취약점 직답

- **권한 부여 기능 동작?** ✅ 정상. 추가/역할변경/활성/삭제 전부 작동(에러처리·재조회 완비). 어드민 중 가장 잘 만든 화면.
- **일반 관리자가 스스로 최고권한으로 승격 가능?** ❌ 불가 — 관리자 테이블 쓰기는 DB 규칙상 super_admin만(서버 강제). 안전.
- **남은 취약점:**
  - 🟠 **P1 (역할 차등 서버 미강제):** 현재 DB는 "활성 관리자냐(is_admin)" / "super냐(is_super_admin)" 2단계만 봄. 그래서 **viewer로 등록해도 실제론 공지·문의·공고 등 운영 CRUD가 다 됨**(역할 구분이 화면에만 있음). → 신뢰할 관리자만 추가하는 한 당장 큰 위험은 아니나, viewer/admin 구분을 진짜로 강제하려면 추가 작업 필요. **권장: 다음 단계 수정.**
  - ✅ P2 (관리자 명단 노출) — 방금 해결.
  - 🟡 P3 (과거 마이그 파일의 super 하드코딩) — **라이브 함수엔 없음**(정리됨). 영향 없음.

## B-4. ★ 종훈님이 직접 할 일
1. **마스킹 해제 보안키 재설정** — 어드민 → 설정 → 보안키. (이전 평문키 삭제됨, 재설정해야 회원정보 "보기" 작동. 안 해도 마스킹 자체는 안전)
2. (선택) 설정 → 유출 비밀번호 보호 켜기(OAuth 위주라 영향은 낮음).
