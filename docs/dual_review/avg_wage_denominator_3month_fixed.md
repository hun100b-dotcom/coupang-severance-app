# 더블리뷰 — 평균임금 분모 "마지막 근무일 기준 3개월 고정" (2026-07-15)

## 대상
`backend/app/services/severance.py` `compute_average_wage` — 퇴직금·실업급여 정밀계산 공통 사용.

## 버그 & 수정 (오너 확정 = 법정 원칙)
- **버그**: 3개월 창 안의 **첫 근무일**로 분모(달력일수)를 축소 → 초반 공백 크면 평균임금 과다.
- **수정**: 분모를 **사유발생일(마지막 근무일 end_date) 이전 3개월 달력일수로 고정**.
  근로기준법 제2조 "산정사유 발생일 이전 3개월 임금총액 ÷ 그 기간의 총일수".
  - `period_start = (end_date - relativedelta(months=3)) + timedelta(days=1)`
  - `calendar_days = (end_date - period_start).days + 1`  (월 길이·윤년에 따라 89~92일 자연 변동)
  - 분자 `total_pay` = 그 3개월 창 지급액 합, 첫 근무일 기준 축소 제거.
  - 산출근거 일관성: 반환 start_date=period_start, end_date=end_date → 표시 기간 span == calendar_days.
  - end_date(마지막 근무일) 판정 로직 불변. 쉬운계산(simple)은 이 함수 미사용 → 불변.

## 검산 (오너 예시)
"3개월 창 90일 중 첫 근무 30일째, 20일 근무 300만원":
- 기존(버그): 3,000,000 / 61 ≈ **49,180원** (분모 축소)
- 수정 후: 3,000,000 / 90 = **33,333원** ✅ (법정 원칙, 실측 일치)

## 최종 판정: **PASS → 커밋·배포**
- A·B 모두 PASS. BLOCKER 0. 반례로 로직 안 깨짐.
- **MINOR(dateutil)**: severance.py가 `dateutil.relativedelta`를 직접 import하므로 `requirements.txt`에 `python-dateutil>=2.8.2` 명시(전이의존 붕괴 방지). → 반영.
- **MAJOR(벡터7)**: `end_dt`(퇴직일)가 마지막 근무일보다 3개월↑ 뒤면 산정창이 근무와 안 겹쳐 기초일액=0. **옛 코드도 동일(calendar_days=0→avg=0)하여 이번 diff 신규 회귀 아님**. 오너가 "end_date 판정 로직 불변" 명시 → 이번 스코프 제외, 별도 티켓(spawn_task).
- **분모 변동**: 89~92일은 달력월 실제 총일수로 "그 기간의 총일수" 법정 정의에 정확 부합. 오너가 relativedelta(정확 3개월)를 명시 확정(90/91 근사 대신). 정책 근거 여기 기록.
