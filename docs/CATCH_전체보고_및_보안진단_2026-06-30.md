## 🔴 치명 — 지금 바로 조치 권장

### V1. 비로그인(anon)도 전체 회원 이메일을 읽을 수 있음
- **무엇:** `public.user_profiles` 뷰가 `id, email, created_at, last_sign_in_at, raw_app_meta_data` 노출. ① `SECURITY DEFINER`(RLS 우회) ② anon에 SELECT 권한.
- **위험:** 비로그인자가 `/rest/v1/user_profiles` 한 번으로 **가입자 전원 이메일·가입일·로그인기록 수집** 가능 → 스팸/피싱/명단유출. (Advisor: auth_users_exposed + security_definer_view, 둘 다 ERROR)
- **개선책:** ① 즉시 anon/authenticated의 user_profiles 권한 회수(앱이 이 뷰 쓰는지 코드 확인 후, 쓰면 백엔드 service-role 경로로 대체) ② 근본: 뷰 `security_invoker=on` 전환 또는 폐기, 최소 컬럼만 RLS 걸린 경로로 제공.

## 🟠 높음

### V2. 감사로그 위조 가능
- `admin_audit_logs` INSERT WITH CHECK true → 인증된 누구나 임의 감사 기록 삽입(흔적 위장).
- **개선책:** INSERT를 is_admin()/service-role 전용으로 제한.

### V3. 알림 임의 삽입
- `notifications` INSERT WITH CHECK true → 아무나 타인에게 알림 생성(피싱/스팸).
- **개선책:** `auth.uid()=user_id` 또는 service-role 제한.

### V4. anon 호출 가능 SECURITY DEFINER 함수
- `write_system_log`(로그 위조), `handle_inquiry_answer`, `touch_session`, `on_*` 트리거 함수가 RPC로 비로그인 호출 가능.
- **개선책:** 외부 호출 불필요 함수는 EXECUTE 회수 또는 SECURITY INVOKER 전환.

## 권장 조치 순서
1. **V1 (즉시)** — anon 회원 이메일 노출 차단. 가장 시급.
2. **V2·V3·V4 (빠른 시일)** — RLS/RPC 권한 조이기(주로 DB, 코드 영향 적음).
