A-1. 어드민 접속 · 권한

  • 주소: /admin — 관리자 로그인 후 접속
  • 현재 관리자 3명 전부 super_admin(최고권한): catchmaster · 종훈님 카카오 · 종훈님 구글
  • 권한 단계: super_admin 전체+관리자 관리  >  admin 운영  >  viewer 열람
단계별 차등은 현재 서버에서 완전히 강제되지 않습니다(아래 B-3 P1 참고). 신뢰할 사람만 관리자로 추가하세요.

A-3. 관리자 추가 / 권한 부여 (단계)

  1. 어드민 → 시스템 → 관리자 계정 메뉴로 이동
  2. "관리자 추가" → 이메일 + 역할(super_admin / admin / viewer) 선택 → 저장
  3. ⚠️ 그 이메일은 먼저 앱에 일반 회원으로 가입(카카오/구글)돼 있어야 로그인 시 매칭됩니다
  4. 역할 변경·비활성화·삭제도 같은 화면에서 처리
  5. 이 작업은 super_admin만 가능 — DB 규칙(RLS)으로 서버에서 강제 ✅
  6. 확인: 추가 후 목록에 표시되고 새로고침해도 유지되면 정상 반영
관리자 계정 화면은 어드민 중 가장 견고하게 만들어졌습니다(에러처리·이중 가드·재조회 완비).

A-4. "디자인이 안 바뀐 것 같다" 설명

결론: 버그 아님, 정상. 개편은 main에 배포됐고 빌드에도 반영됐습니다(미반영·캐시 문제 아님).

다만 사용자 화면과 달리 레이아웃은 그대로 두고 색·대비·숫자정렬만 통일한 "절제된" 방식이라 시각 변화가 작게 느껴집니다(정보가 빽빽한 관리화면 특성).

  • 배경 #f8fafc → #EEF1F5 (약간 푸른 회색)
  • 무지개색 제거 → 절제된 파랑/그린/앰버
  • 금액·숫자 자릿수 정렬(tabular)
확인법: 어드민에서 Ctrl + Shift + R(강력 새로고침) 후 배경이 살짝 푸른 회색 + 숫자가 가지런하면 반영된 것입니다.

사용자 화면처럼 확 달라 보이게 하려면 토큰 통일이 아니라 별도 레이아웃 개편이 필요합니다(원하면 진행).

B-1. 보안을 어디서 확인하나

현재 보안 기능이 메뉴별로 흩어져 있습니다(한눈에 보는 통합 화면은 아직 없음).

무엇위치
누가 관리자인가 / 권한 부여시스템 → 관리자 계정
회원 개인정보 보호 / 마스킹 해제시스템 → 회원 관리
관리자가 무슨 행동을 했나(감사)시스템 → Audit Logs / 서버 로그

💡 원하면 이것들을 한 화면에 모은 "보안 현황" 대시보드(관리자 수·최근 감사·차단 IP·노출 점검)를 만들어 드릴 수 있습니다.

B-3. 권한 부여 — 동작 / 취약점 직답

  • 권한 부여 기능 동작? 정상 추가/역할변경/활성/삭제 전부 작동(에러처리·재조회 완비)
  • 일반 관리자가 스스로 최고권한 승격? 불가 관리자 테이블 쓰기는 super_admin만(서버 강제)
  • 관리자 명단 노출(P2)? 방금 해결 비로그인 읽기 차단(is_admin 전용)

🟠 남은 취약점 — P1 (역할 차등 서버 미강제)

현재 DB는 "활성 관리자냐(is_admin) / super냐(is_super_admin)" 2단계만 봅니다. 그래서 viewer로 등록해도 실제론 공지·문의·공고 등 운영 CRUD가 다 됩니다(역할 구분이 화면에만 존재).

신뢰할 관리자만 추가하는 한 당장 큰 위험은 아니지만, viewer/admin을 진짜로 차등하려면 서버(RLS) 추가 작업이 필요합니다. 권장: 다음 단계 수정.

참고: 과거 마이그레이션 파일의 super 하드코딩(P3)은 라이브 함수엔 없음(정리됨). 영향 없습니다.

B-4. ★ 종훈님이 직접 할 일

  1. 마스킹 해제 보안키 재설정 — 어드민 → 설정 → 보안키. (이전 평문키 삭제됨 → 재설정해야 회원정보 "보기" 작동. 안 해도 마스킹 자체는 안전)
  2. (선택) 설정 → 유출 비밀번호 보호 켜기 (OAuth 위주라 영향은 낮음)
