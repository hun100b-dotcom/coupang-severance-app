## 2. DB 마이그레이션 계획

### 마이그레이션 1: job_postings 섹션 + 복리후생
```sql
-- 파일: supabase/migrations/20260410_job_postings_section_benefits.sql
ALTER TABLE job_postings
  ADD COLUMN IF NOT EXISTS section text DEFAULT 'always' 
    CHECK (section IN ('today-urgent', 'tomorrow-urgent', 'always')),
  ADD COLUMN IF NOT EXISTS benefits text[] DEFAULT '{}';
```

### 마이그레이션 2: job_applications 인적사항 컬럼
```sql
-- 파일: supabase/migrations/20260410_applications_personal_info.sql
ALTER TABLE job_applications
  ADD COLUMN IF NOT EXISTS applicant_name text,
  ADD COLUMN IF NOT EXISTS applicant_birth date,
  ADD COLUMN IF NOT EXISTS applicant_gender text CHECK (applicant_gender IN ('male','female')),
  ADD COLUMN IF NOT EXISTS applicant_phone text,
  ADD COLUMN IF NOT EXISTS consent_collect boolean DEFAULT false,
  ADD COLUMN IF NOT EXISTS consent_third_party boolean DEFAULT false,
  ADD COLUMN IF NOT EXISTS consent_at timestamptz;
-- (NOT NULL 제약은 기존 데이터 있어서 DEFAULT NULL로 추가)
```

## 5. 보안 고려사항

- 주민번호 뒤 1자리 절대 미수집 (성별코드 — applicant_gender로 대체)
- birth_date: YYYY-MM-DD 6자리 생년월일만 (1990-01-01 형식, 주민번호 아님)
- RLS: job_applications는 본인 데이터만 CRUD, 어드민은 전체 조회
- 동의 미체크 시 지원 버튼 비활성 (프론트 + 추후 DB 체크)
- xlsx 다운로드: consent_third_party=true 건만 (동의한 건만 내보내기)
- 개인정보 보유기간: 채용 종료 후 6개월 파기
