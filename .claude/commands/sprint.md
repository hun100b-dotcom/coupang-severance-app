# Sprint — 기획서 기반 자동 구현

$ARGUMENTS 에 기획서 경로 또는 작업 설명을 전달하세요.

## ⛔ 0단계: 기획서 존재 확인 (가장 먼저 실행)

> 이 단계를 건너뛰는 것은 절대 금지. sprint 시작 전 반드시 수행.

1. `$ARGUMENTS` 가 `tasks/plans/` 경로를 포함하는지 확인
2. 포함하면 → 해당 파일 존재 여부 확인 후 진행
3. 포함하지 않으면 → `tasks/plans/` 폴더의 최근 파일 목록 출력 후 판단:
   - 관련 기획서가 있으면 → 해당 기획서 사용
   - 관련 기획서가 없으면 → **즉시 중단**하고 아래 메시지 출력:

```
⛔ 기획서 없음. 아래 명령어로 기획서를 먼저 작성하세요:

/plan [작업 설명]

예시: /plan 마이페이지 탭에 추천인 통계 추가
```

4. 단, $ARGUMENTS 에 기획 내용이 직접 포함된 경우(3줄 이상 상세 설명):
   - `tasks/plans/YYYY-MM-DD-[작업명].md` 에 기획서로 먼저 저장
   - 저장 완료 후 진행

---

## 1단계: 기획서 로딩

- 기획서 파일 읽기
- CLAUDE.md 핵심 규칙 확인 (28일 블록, any 금지, 한국어 주석 등)
- 하네스 적용 대상인지 재확인 (2파일 이상 → 기획서 필수임을 재검증)

## 2단계: 영향 범위 분석

- 변경 예상 파일 목록 나열
- 5개 이상이면 경고 후 분할 제안
- DB 변경 필요 시 마이그레이션 SQL 먼저 작성

## 3단계: 구현

- 파일별 순차 구현 (한 파일씩)
- 각 파일 완료 시 `npm run build` 또는 `npx tsc --noEmit`으로 즉시 검증
- 빌드 실패 시 즉시 수정 (다음 파일로 넘어가지 마)

## 4단계: 자동 리뷰 호출

- 구현 완료 후 reviewer 에이전트 자동 호출
- reviewer가 FAIL 반환 시 → 수정 → 재호출 (최대 2회)
- 2회 실패 시 사용자에게 보고

## 5단계: 완료 보고

```
## ✅ Sprint 완료

| 항목 | 내용 |
|------|------|
| 기획서 | [tasks/plans/파일명] |
| 작업 | [작업 설명] |
| 변경 파일 | [파일 목록] |
| 리뷰 결과 | [PASS/FAIL] |
| 다음 단계 | [커밋/추가 작업] |
```
